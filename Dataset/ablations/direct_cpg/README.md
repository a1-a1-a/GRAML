# Direct Evidence Dataset Variants

This folder is generated by `Dataset/scripts/build_evidence_dataset.py`.

## Purpose

The original GRAML training data gives the final LLM mostly raw code. These variants inject a structured CPG evidence block directly into the `input` field so the final LLM sees code-centered evidence instead of relying only on GPT-generated descriptions.

## Generated Variants

- `*_cpg_evidence.json`: code plus Joern/CPG evidence from an external evidence file.
- `*_random_lines.json`: code plus random lines, used as a control ablation to test whether the evidence itself is useful or just extra text.

## Leakage Rule

Detection samples do not include ground-truth vulnerable lines, labels, patches, CVE descriptions, or vulnerable-line-derived `critical_lines` by default. If an external evidence file contains Joern fields such as `cpg_edges`, `data_flow_edges`, `control_flow_edges`, or safe precomputed `graph_context`, they can be injected through `--evidence_path`.

## Example

Generate Joern/CPG evidence for vulnerable description samples first:

```bash
python Dataset/scripts/generate_joern_cpg_evidence.py \
  --input_path Dataset/id/Ultimate_train.json \
  --input_path Dataset/id/Ultimate_valid.json \
  --input_path Dataset/id/Ultimate_test.json \
  --output_path Dataset/graph_context/cpg_evidence/joern_cpg_evidence.json \
  --work_dir Dataset/graph_context/cpg_evidence/joern_work \
  --task_filter description \
  --skip_benign_description \
  --include_label_lines
```

Build direct CPG-evidence datasets:

```bash
python Dataset/scripts/build_evidence_dataset.py \
  --input_path Dataset/id/Ultimate_train.json \
  --output_path Dataset/ablations/direct_cpg/Ultimate_train_cpg_evidence.json \
  --variant cpg_evidence \
  --evidence_path Dataset/graph_context/cpg_evidence/joern_cpg_evidence.json \
  --evidence_task_policy description_only \
  --preserve_raw_when_no_evidence \
  --max_suspicious_lines 6 \
  --max_relations 8
```

For the train-only supervision setting, generate Joern evidence only from vulnerable description samples in `Ultimate_train.json`, inject it into the description task, and keep validation/test JSON files unchanged. This evaluates whether CPG-grounded vulnerability descriptions improve final detection without requiring graph evidence at inference time.
